### 3. 协作单 42.0 被 REOPENED 的 P1 缺陷修复与契约校准（P1）

**缺陷：`logout` / `logout-all` 未下发清 Cookie 头**（方舟浏览器 + curl 双证据发现）
- 根因：对 FastAPI **注入的** `Response` 调 `clear_session_cookie(response)` 后，又 `return Response(status_code=204)` 返回**新对象** → 注入对象上的 `Set-Cookie` 被丢弃 → 登出后 HttpOnly Cookie 未清，按 F5 回到应用内
- 修复：改为在注入对象上 `response.status_code = 204` 并**原样 `return response`**（`logout` 与 `logout-all` 同），并在代码注释固化该 FastAPI 陷阱防回归
- live 实证：`set-cookie: access_token=""; HttpOnly; Max-Age=0; Path=/; SameSite=lax`；同一 cookie jar 登出后 `/auth/me` → **401 `unauthenticated`**（修复前 200）

**服务端防自锁**
- `update_user` 新增守卫：禁止禁用/降级**当前登录账号** → **400 `cannot_modify_self`**；role 合法性校验前置到函数顶部（无效 role → 400 `bad_format`）
- 「至少保留 1 个启用 admin」经推导为**不可达条件**（操作者本身必为启用态 admin 且无法禁用/降级自己；target≠actor 时 others≥1），故未加额外 last-admin 计数查询（YAGNI），该不变量由上述规则结构性保证

**契约文档校准（3 处）**
- 方案 §7：`401 disabled` → **`403 disabled`**
- 方案 §4.3 PUT 行补充 `400 cannot_modify_self`
- 方案 §4.3 新增「状态码口径（实现校准）」：业务响应走统一信封 `{code, message, data}`、**HTTP 恒 200**、成功语义由 body `code` 表达；仅 `logout`/`logout-all`/`change-password` 返回 **HTTP 204**；失败一律 `HTTPException` → body `{detail: {code, message}}`
