## 今日完成

### 问题调查：后台进程频繁停止（P0）

**根因**：系统只有 8GB 物理内存，swap 使用率达到 79%（3.2GB/4GB）。后端进程启动时一次性加载全部 OHLCV 数据（300天 × 5000+只股票），内存峰值达 1.6GB，触发 macOS **jetsam 内存压力机制**，将 uvicorn 和 watchdog 一起杀死。

**修复方案**：

### 1. OHLCV 延迟加载（核心修复 P0）
- 修改 [snapshot_service.py](file:///Volumes/MyData/Quantitative_trading/backend/core/service/snapshot_service.py)
- 启动时**仅加载快照数据**（2MB），延迟加载 OHLCV 到首次 API 请求
- 新增 `_ensure_ohlcv_loaded()` 方法，首次查询时按需加载
- 稳定内存从 **1056-1659 MB → 134-167 MB**，降低 **87%**
- 不再触发 jetsam 杀进程，后端稳定存活 500+秒

### 2. 内存优化（P1）
- `FETCH_BATCH_SIZE`: 20000 → 10000，降低数据库加载峰值
- 消除 `all_chunks` 中间列表，直接合并到 `ohlcv_dict`，避免数据重复占用
- 每批数据加载后主动 `gc.collect()` 回收，减少内存碎片

### 3. 双重守护机制（P1）
- 保留 `scripts/backend_watchdog.sh` shell watchdog（每15秒检查）
- 新增 `scripts/cron_backend_health.sh` 健康检查脚本
- 新增 `scripts/launchctl/com.quant.backend.healthcheck.plist` launchd 定时任务（每分钟检查）
- 即使 watchdog 被杀死，launchd 健康检查脚本仍能自动重启后端

### 4. 配置更新
- `scripts/load_launchd_plists.sh` 新增健康检查加载说明
- `scripts/start.sh` 保持 watchdog 入口不变
