## 今日完成

### 服务启停脚本改造（P0）
- 排查并解决 `./scripts/start.sh dev start` 前台/后台均启动失败的根因：**PostgreSQL@18 未运行**（brew services 显示 none，端口 5432 拒绝连接），后端初始化 PG 连接池失败导致应用崩溃，watchdog 反复重启；前端因 `dev_start_backend && dev_start_frontend` 短路逻辑也未启动
- 通过 `pg_ctl` 直接启动 PostgreSQL（绕过 launchd，解决 TRAE 沙箱无法写 LaunchAgents 的 `Operation not permitted` 限制）
- 清理 2 个重复的 watchdog 进程（PID 1093、1763）及残留 PID 文件

### start.sh 整合数据库管理（P0）
改造 `scripts/start.sh`，实现三项目标：
1. **启动前检查数据库**：新增 PostgreSQL 管理区（`pg_is_ready` 就绪检测降级 nc、`start_database` 自动拉起、`stop_database` fast 停止），`dev_start_backend` 和 `dev_start_backend_fg`（前台调试）启动前均调用 `start_database || return 1`，从根上杜绝"数据库未启动导致后端反复崩溃"问题
2. **stop 连带停库**：抽出 `dev_stop_app`（只停前后台），`dev_stop` = 停前后台 + `stop_database` 停库
3. **restart 仅重启前后台**：`dev_restart` 改用 `dev_stop_app`，数据库保持运行，避免不必要的 PG 重启

### 验证（三种场景实测通过）
- `dev start`：数据库未运行自动拉起 → 后端健康 → 前端 HTTP 200
- `dev stop`：前后台 + PostgreSQL 全部停止（端口 8000/5173 释放，pg_isready 无响应）
- `dev restart`：数据库保持"运行正常"，仅重启前后台
- 语法检查 `bash -n start.sh` 通过
