### P0：修复 pandas 2.2 + SQLAlchemy 2.0 参数化查询回归（数据管道全线恢复）
- **现象**：全市场技术指标计算大量股票日志报「行情数据不足 仅获取到 0 条」，全部被跳过。
- **根因**：`pd.read_sql(query, engine, params=<list>)` 在 pandas 2.2 + SQLAlchemy 2.0 下被按 executemany 多参数集处理，扁平标量 list 抛 `List argument must consist only of tuples or dictionaries`，导致 `get_quotes` 等数据访问方法返回空。属 pandas 1.x→2.x 升级破坏性回归（上一 commit cf55240 引入 SQLAlchemy engine 后暴露）。
- **修复**：`postgresql_storage.py` 新增统一 helper `_run_query_df`（原生 psycopg2 cursor），改写全部 10 处 `read_sql(engine, params=<list/tuple>)`；helper 内补 Decimal→float 转换，恢复 pandas read_sql 数值类型行为。
- **验证**：全链路重跑通过 指标 5197 只 104 万条 → 信号 3006 条 → 宽表 5208 条 → parquet 5208 条 / 92 列 → 后端 API 筛选正常返回。
