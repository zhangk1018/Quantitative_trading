## 今日完成

### 1. 多选自编指标选不出股票（交集为空）根因定位与修复（P0）

**触发**：K 反馈「条件构建器单独选『10条件选股』或『多因子蓄势突破』都能选出股票、且两者有交集；但两个一起选就选不出股票」。

**根因**：数据窗口是**全局共享**的，导致每个指标的结果随「同时勾选了哪些指标」而变。

- `useScreenerData.computeMaxLookback()` 对**当前所有已选**自编指标取各自公式里数字的最大值 `+5`，只产出一个**唯一**窗口；
- `sliceOhlcv()` 用这一个窗口切全部候选，再把**同一份切片数据**交给每个指标；
- 组合窗口恒为 `max(各指标自身窗口)`，**再加一个指标就会拉长另一个指标的输入窗口**。对「看整段窗口」的公式（突破窗口内前高/新低、全窗极值/均值、依赖 `len(close)` 等）会显著变严，命中集合骤减，交集不再是单独跑时看到的相交集合，极端为 0。

**修复（前台）**：

| 文件 | 改动 |
|---|---|
| `frontend/src/features/stock-picker/services/CustomIndicatorService.ts` | 新增 `computeConditionLookback(cond)`（只按**本指标自身**公式取窗口）；`computeAndFilter` 内**每个指标各自切片**后再计算；接受**完整未切片** OHLCV |
| `frontend/src/features/stock-picker/hooks/useScreenerData.ts` | 移除全局 `computeMaxLookback` + 全局 `sliceOhlcv`，改传完整 OHLCV（切片下沉到服务内、按指标各自进行） |
| `frontend/src/features/strategy-backtest/utils/customIndicatorRunner.ts` | 移除**逐批前导 null 补齐**：worker 逐只调用 `calculate`，前导 null 会让按位置从 0 起算的公式（如 ADX 预热 `tr[:14]` 含 NaN）静默失效、分数偏移；改为每只股票保持自身 K 线长度 |

**行为保证**：单指标时全局窗口本就等于其自身窗口，**修复前后单指标结果完全一致**；组合结果恒等于「各指标单独结果的交集」。

用 Playwright 驱动系统 Chrome，admin 登录本地前端，把 localStorage 里的**真实指标**注入后回归（沪深全市场：候选 5210、K 线 4978 只）：

### 3. 选股执行效率优化（超时 / 卡死）（P1）

**现象与真因**：单指标在全市场就需 ~7 分钟且计算期间进度条文案长时间不动，观感即「卡死/超时」；瓶颈是**单线程 Pyodide 执行纯 Python 循环型重公式**（`rolling_max_safe`/`ema`/ADX 全 Python 循环），4978 只 × ~105 根；且原单批超时仅 30s，重公式下易误杀整轮。

**优化**：

- **Pyodide Worker 池并行**：`getPoolSize()` 按核数取 2~4 个 Worker，批次轮转分发、Worker 间并行（单 Worker 内串行）。→ 端到端 **~2.0–2.4×**（本机 2 物理核/4 逻辑核 → 池为 3；核多机器更快）。
- **单批超时 30s→120s、批次 100→50**：单批更短更稳，不再误杀整轮。
- **按批进度透传**：`runner.execute` 的每批进度接到 UI（「已计算 x/y 批」），不再假死。
- **OHLCV 分批并发拉取**（4 并发）。
