### 1. 美股基本面 ETL 失败修复 + 数据补齐（P0）

**触发**：K 晨报「看板 美股数据监控 → 基本面 ❌ 失败」。

**根因**：新浪美股列表接口（`ak.stock_us_spot()` 背后逐页抓取的 `US_CategoryService.getList`，当日 914 页）**个别分页偶发返回上游错误对象**：

```json
{"__ERROR":"HY000","__ERRORMSG":"SQLSTATE[HY000]: General error: 2006 MySQL server has gone away","__ERRORFILE":"\/data1\/...mysql.inc.php","__ERRORLINE":382}
```

该响应**没有 `data` 字段**，而 AkShare 官方 `stock_us_spot()` 的分页循环不做容错（直接取 `data_json["data"]`）→ 抛 `KeyError: 'data'`，**单页异常即整任务失败**。10-08 当日 3 次重试（08:46:24 / 08:58:16 / 09:04:11）分别在不同分页撞上异常页，故全部失败；前两日（10-06 / 10-07）均正常，属上游偶发抖动，非本地方案失效。

证据：`logs/us_job.log` 的 traceback 指向 `akshare/stock/stock_us_sina.py:112`；独立探针逐页扫描复现——第 5 页返回上述 `__ERROR` 对象。

**影响**：`stock_daily_basic` 的 `us` 数据止于 2026-10-06，10-07 缺失（宽表/Parquet 的市值、PE 停留在旧值）。

**修复**（`backend/collector/etl/sync_us_basic.py`）：改为**自实现分页**（复用官方接口一致的请求签名与 URL），弃用无容错的 `ak.stock_us_spot()`：

- 逐页请求，单页失败重试 3 次（间隔 1s）；
- 重试用尽仍失败的页**跳过并累计**；
- **跳过页占比 > 10% 判定快照不完整，抛错放弃写入**（宁缺勿残，交次日重跑）；
- 单页 20s 超时（防 10-01 式半死连接永久阻塞）；
- 覆盖率 < 90% 显式告警（对齐项目规范「覆盖率 <90% 必须告警」）。

**数据补齐（已执行）**：live 补跑 `--date 2026-10-07`，**914/914 页成功**、无异常页，写入 209 条；校验 10-07 的 `total_mv` / `pe` / `close` 均为 209 条非空。

### 2. 前端服务纳入 launchd 托管（P1）

**需求**：K 要求「启动时前台也自动启动」。原状：`com.quant.postgresql` 与 `com.quant.backend` 已由用户域 launchd 托管（登录自启 + KeepAlive），而前端只能靠 `start.sh` 的 `nohup npm run dev` 手动拉起 —— 重启/登录后前端不自启。

| 文件 | 改动 |
|---|---|
| `scripts/launchctl/com.quant.frontend.plist`（新增） | `RunAtLoad` + `KeepAlive`，登录即拉起 `npm run dev --host 0.0.0.0 --port 5173`，日志落 `logs/frontend/quant_frontend{,.err}.log` |
| `scripts/load_launchd_plists.sh` | 后端段之后新增前端加载段（`unload` + `load`） |
| `scripts/start.sh` | 前端启停全面转 launchd：`dev start` 只等 launchd 拉起 5173；`dev stop` 提示 `launchctl unload`；`dev restart` 前后端均 `kickstart`；`dev status` 标注监督来源；`dev frontend fg` 提示先卸载；`FRONTEND_START_TIMEOUT` 8 → 30 |

**验证**（安装命令由 K 在本机终端执行，沙箱禁止写 `~/Library/LaunchAgents` 与调用 `launchctl`）：

- `launchctl list` → `5827　0　com.quant.frontend`（已加载）；
- `lsof -i :5173` 有 node 监听；`curl -I` → `HTTP/1.1 200 OK`，页面 `<title>量化交易系统</title>`；
- `./start.sh dev status` → 前后端均显示「由 launchd … 监督（KeepAlive 常驻）」；
- **KeepAlive 实测**：kill 掉 vite（PID 5836）后 **3s 自动拉起新 PID 5995**，HTTP 200。
