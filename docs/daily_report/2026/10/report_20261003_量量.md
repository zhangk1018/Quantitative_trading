## 今日完成

### 1. 港/美股周线"未生成"根因定位（P0）

**触发**：K 周六晨报「今天是周六，港股和美股的周线现在还为生成」，并询问其调度安排。

**查证结论：报障属实，且是结构性问题**。周/月K 聚合原本只有**一条 A 股日历驱动**的路径（`trade_calendar` 判「本周/本月最后一个交易日」），聚合 SQL 无 market 过滤、周期区间亦取自 A 股日历 —— 港/美股只是被"顺带"写出来。由此产生三类缺陷，均有原始证据：

1. **孤儿日（永久丢）**：A 股休市而港/美开市的交易日，既不触发聚合、也落在任何周期区间之外。实测 hk `1d` 有 2026-09-25 / 10-02、us 有 09-25 / 10-01 / 10-02，但 `1w` 最新只到 2026-09-30；下次门禁打开是 10-09，其聚合区间为 `2026-10-08~10-09`，这些日子**永久遗漏**。2025-10 以来此类孤儿日 hk 12 天 / us 19 天。
2. **美股末日缺收盘**：美股 T 日数据 T+1 08:30 才落库，而旧触发点是周五 18:30 → 美股周线系统性缺最后一天收盘，仅靠"次日意外重跑"偶然补上（10-01 日志显示对 09-28~09-30 又聚了一次）。
3. **打标与看板错位**：港/美股周线沿用 A 股末交易日打标（09-30），与看板「最新交易日」新鲜度判定不一致。

**量化对账**（以「1d 应派生的 (code, ISO周) 集合」比对周线实际覆盖）：重建前 **hk 缺失 2,986 对 / us 缺失 616 对**。

### 2. `compute_bar_aggregation.py` 分市场重构（P0）

新增 `--market`（默认 `cn`，支持 `hk,us` 列表）、`--lookback-periods`、`--rebuild --from/--to`，拆为两条互不干扰的分支：

- **cn（含 `index`）**：逻辑与旧版完全一致（A 股 `trade_calendar` + `trade_week_id` 连续交易日分组 + 自然月），仅把聚合与覆盖度 SQL 显式限定 `market IN ('cn','index')`，**不再顺带写港/美股**；现有 cn plist 不传 `--market`，零改动。
- **hk / us**：按**该市场自己的数据源交易日历**（港股 HSI / 美股 .IXIC，与 `import_{hk,us}_daily` 同源、可降级锚定个股）划分周期：
  - 周期桶 `1w` = ISO 周、`1m` = 自然月；打标日 = 该桶内该市场最后交易日；
  - 结算判据：`1w` = 该 ISO 周周六已到；`1m` = 自然月末已到；
  - **完整度门禁（齐备才写）**：桶内该市场每个交易日必须已落库，否则整桶跳过并记日志；交易日集合取「日历 ∩ 桶」∪「库中已有」，日历偶发缺日不会漏聚合；
  - **先删后插**：按桶的自然日跨度删除该市场旧行（含旧版错位行）再写入，一个周期只有一条；
  - **幂等自愈**：每次回看重算最近 N 个周期（`1w` N=4 / `1m` N=3），迟到/修正数据自动吸收；
  - 日历不可用（返回 None）→ 只告警跳过，**绝不猜测、不写入**。
