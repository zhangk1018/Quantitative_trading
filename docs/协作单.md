# 协作单

> 方舟与量量之间的工单系统，基于增强黑板模式。
> 最后更新：2026-09-14
> 注：已 CLOSED 的工单移入 `docs/协作单_归档.md` 存档，不在本文件维护；本文件仅保留 NEW/ASSIGNED/VERIFY（进行中或待验证）的工单。

***

## 工作流

### 状态机

```
NEW（方舟/量量提单）
  │
  ▼
ASSIGNED（量量/方舟 认领并开始处理）
  │
  ▼
VERIFY（处理完成，待对方验证）
  │
  ├─ ✅ → CLOSED（验证通过，关闭）
  │
  └─ ❌ → REOPENED（验证不通过 → 回到 ASSIGNED）
```

### 各角色职责

| 角色     | 在工单中的职责                                                 |
| ------ | ------------------------------------------------------- |
| **方舟** | 发现前端/后端问题 → 提单（NEW）；量量修复后做前端侧验证（VERIFY→CLOSED/REOPENED） |
| **量量** | 修复后端/数据问题（ASSIGNED→VERIFY）；方舟提的后端问题，量量认领修复              |
| **K**  | 仲裁争议（REOPENED 后双方无法达成一致时）；最终验收                          |

### 生命周期规则

1. **提单方**（通常是发现方）写入工单时状态为 `NEW`
2. **处理方**认领后改为 `ASSIGNED`，开始修复
3. **处理方**完成修复并验证后改为 `VERIFY`，**同时**在 topics.md 追加一行通知对方
4. **验证方**从前端/使用侧验证后：

   - 验证通过 → `CLOSED`

   - 验证不通过 → `REOPENED`，注明原因，**同时**在 topics.md 追加一行通知处理方
5. 一个工单最多 REOPENED 2 次，第 3 次需要 K 介入仲裁

## [35.0-BACKTEST-CONSIST-20260913] 回测买入条件与选股视图口径不一致（回测引擎重算 vs 后端预计算）

| 字段 | 内容 |
|------|------|
| **状态** | VERIFY（后端历史快照端点完成，待方舟前端联调验证） |

| **优先级** | P1 |

**定位路径**:
- 前端回测引擎：`frontend/src/features/strategy-backtest/engine.ts`（`getFieldValue` L367-399、逐日判定 L1413-1430、T+1 成交 L916）
- 条件剥离/下推：`frontend/src/features/strategy-backtest/utils/filterTreeAdapter.ts`（`stripUnsupportedFieldsForEngine` L190、`extractPushdownPredicates` L255）
- 候选池与 OHLCV 加载：`frontend/src/features/strategy-backtest/utils/dataLoader.ts`（`loadBacktestData` L303、`/api/stocks/` L340、`/api/snapshot/all` L419）
- 自编指标回测预计算（索引错位点）：`frontend/src/features/strategy-backtest/utils/customIndicatorRunner.ts`（L349-372 用完整 OHLCV 按序生成评分数组）
- 选股视图（口径基准）：`backend/core/service/screener_service.py`（`/api/stocks/` 过滤最新一日预计算宽表）

**问题描述**:
「选股视图」与「回测分析」用同一套「X条件选股」买入条件时，逐日判定结果不一致（K 实测：选股 09-01 选出 A，回测 09-01 却不买入 A）。根因是两者数据来源与口径不同：
1. **选股视图**用 `/api/stocks/` 对**后端 ETL 预计算好的最新一日 parquet 宽表**过滤（`rsi/macd(dif,dea)/boll/kdj/cci`、各 `pattern` 列、技术形态、`pe/pe_ttm/pb/换手率/市值` 等，口径 100% 来自后端），前后端天然一致。
2. **回测**因后端仅导出最新一日预计算宽表（无历史每日出口），退化为：`/api/stocks/` 仅粗筛候选池 → `/api/snapshot/all` 拉原始 OHLCV → **前端从 OHLCV 重算技术指标 + 自编指标**做逐日判定。导致：
   - 技术/形态口径与后端预计算不一致（前端重算 vs ETL 预计算）；
   - 基本面 `pe/pe_ttm/pb/turnover_rate` 被 `stripUnsupportedFieldsForEngine` 剥离，而 `extractPushdownPredicates` 只下推 `market_cap/close` → 这几条在回测里**彻底失效**；
   - 自编指标评分数组基于**完整 OHLCV** 生成，而引擎用**过滤后子序列索引**访问 → **评分日期错位**，逐日分数对不上正确日期。
3. 即便命中，回测也是 T 日信号、T+1 开盘成交（design，非缺陷）。
