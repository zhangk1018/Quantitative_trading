## 工作流

### 状态机

```
NEW（方舟/量量提单）
  │
  ▼
ASSIGNED（量量/方舟 认领并开始处理）
  │
  ▼
VERIFY（处理完成，待对方验证）
  │
  ├─ ✅ → CLOSED（验证通过，关闭）
  │
  └─ ❌ → REOPENED（验证不通过 → 回到 ASSIGNED）
```

### 各角色职责

| 角色 | 在工单中的职责 |
|------|---------------|
| **方舟** | 发现前端/后端问题 → 提单（NEW）；量量修复后做前端侧验证（VERIFY→CLOSED/REOPENED） |
| **量量** | 修复后端/数据问题（ASSIGNED→VERIFY）；方舟提的后端问题，量量认领修复 |
| **K** | 仲裁争议（REOPENED 后双方无法达成一致时）；最终验收 |

### 生命周期规则

1. **提单方**（通常是发现方）写入工单时状态为 `NEW`
2. **处理方**认领后改为 `ASSIGNED`，开始修复
3. **处理方**完成修复并验证后改为 `VERIFY`，**同时**在 topics.md 追加一行通知对方
4. **验证方**从前端/使用侧验证后：
   - 验证通过 → `CLOSED`
   - 验证不通过 → `REOPENED`，注明原因，**同时**在 topics.md 追加一行通知处理方
5. 一个工单最多 REOPENED 2 次，第 3 次需要 K 介入仲裁

### 二、状态机引擎（核心）

**状态枚举**：`PLAN → DO → CHECK → ACT → PLAN`（闭环）

**状态流转规则**：
```
PLAN   → DO        （计划完成后才能执行）
DO     → CHECK     （执行完成后才能复盘）
CHECK  → ACT       （复盘后进入改进）
ACT    → PLAN      （改进完成 → 新周期）
```

**状态机 API**：`PUT /api/pdca/cycles/{id}/transition`

**请求体**：
```json
{ "target_status": "DO" }
```

**边界条件检查**：
- `PLAN → DO`：检查周期内是否有交易计划（`pdca.trading_plan` 至少一条）
- `DO → CHECK`：检查周期内所有交易是否已平仓（`exit_date IS NOT NULL`）
- `CHECK → ACT`：检查复盘报告是否已填写（`pdca.pdca_check_report` 存在）
- `ACT → PLAN`：自动创建下一个周期的草稿，链接 `prev_cycle_id`

**错误响应**：状态跳变非法时返回 400，附具体原因（如`不允许从 PLAN 直接跳转到 CHECK`）

```python
@router.post("/records/{record_id}/exit-slips/batch", response_model=ApiResponse)
async def batch_create_exit_slips(record_id: int, batch: ExitSlipBatchCreate):
    """批量新增卖出子单，事务内完成 remain_qty 更新 + gross_profit 重算"""
    with get_db() as conn:
        with conn.cursor() as cur:
            # 1. 检查买入单存在且 remain_qty 充足
            cur.execute("SELECT id, quantity, remain_qty, commission_entry FROM pdca.trading_record WHERE id = %s AND deleted_at IS NULL", (record_id,))
            record = cur.fetchone()
            if not record:
                raise HTTPException(status_code=404, detail="40011: 交易记录不存在")
            
            _, total_qty, remain_qty, commission_entry = record
            
            # 2. 校验总卖出数量不超过 remain_qty
            total_sell_qty = sum(s.quantity for s in batch.slips)
            if total_sell_qty > remain_qty:
                raise HTTPException(status_code=400, detail=f"40013: 卖出数量 {total_sell_qty} 超过剩余持仓 {remain_qty}")
            
            # 3. 批量插入子单
            for slip in batch.slips:
                cur.execute(
                    """INSERT INTO pdca.trading_exit_slip 
                       (record_id, exit_date, exit_price, quantity, commission, exit_reason, exit_score, actual_stop_loss, slip_point)
                       VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s)""",
                    (record_id, slip.exit_date, slip.exit_price, slip.quantity, 
                     slip.commission, slip.exit_reason, slip.exit_score, 
                     slip.actual_stop_loss, slip.slip_point)
                )
            
            # 4. 更新 remain_qty
            new_remain = remain_qty - total_sell_qty
            cur.execute("UPDATE pdca.trading_record SET remain_qty = %s WHERE id = %s", (new_remain, record_id))
            
            # 5. 重算 gross_profit（聚合所有子单利润）
            cur.execute(
                """SELECT COALESCE(SUM(
                    (exit_price::numeric - %s) * quantity - commission
                ), 0) FROM pdca.trading_exit_slip 
                   WHERE record_id = %s AND deleted_at IS NULL""",
                (record[3], record_id)  # record[3] = entry_price from earlier
            )
            total_profit = float(cur.fetchone()[0]) - float(commission_entry)
            cur.execute("UPDATE pdca.trading_record SET gross_profit = %s WHERE id = %s", (round(total_profit, 4), record_id))
            
            conn.commit()
            return ApiResponse(code=200, message="success", data={
                "record_id": record_id, "remain_qty": new_remain, "gross_profit": round(total_profit, 4)
            })
```
